# 🌼 Good Reps

A cheerful, offline-first workout tracker made as a gift. It installs on an iPhone from Safari
(Add to Home Screen), needs no account, and keeps everything on the phone.
Two cartoon dogs cheer her on.

- **React + Vite + TypeScript**, Tailwind v4, Framer Motion
- **Installable PWA**: manifest, service worker (precaches the whole app → works fully offline)
- **IndexedDB via Dexie**, behind a small storage interface, with JSON export/import backups
- Built and tuned for **iPhone Safari in standalone mode**

---

## Quick start

```powershell
npm install
npm run dev        # http://localhost:5173 (also on your Wi-Fi, so you can open it on a phone)
npm test           # progression / milestone / streak / storage tests
npm run build      # type-checks, then builds to dist/
npm run preview    # serve the production build (service worker active)
```

To preview everything, open **Settings → Load demo data**. That adds about 10 weeks of sample workouts and goals.
**Clear demo data** (in Settings or on the home banner) removes only the demo rows.

## Deploying (static site)

The build output is a plain static folder (`dist/`). The app must be served over **HTTPS**
(all three hosts below do this automatically) for the service worker and install to work.

### Netlify (easiest, drag-and-drop)
1. `npm run build`
2. Go to <https://app.netlify.com/drop> and drag the `dist` folder onto the page.
3. Optional: *Site settings → Change site name* to get a friendlier URL.

### Vercel
1. Push this folder to a GitHub repo.
2. On <https://vercel.com/new>, import the repo. Framework preset **Vite**, build command `npm run build`, output `dist`.
3. Deploy. Every push redeploys.

### GitHub Pages (how this repo is deployed)
`.github/workflows/deploy.yml` runs the tests, builds with the repo name as the base path, and publishes
`dist/` on every push to `main`. The site is at `https://<user>.github.io/<repo>/`.
One-time setup: *Settings → Pages → Source: GitHub Actions*.

### Updating after she’s installed it
Just redeploy. The service worker fetches the new version in the background and it applies on her
next launch. Her data is untouched.

## Installing on her iPhone
1. Open the site in **Safari** (not Chrome; on iPhone only Safari can add web apps to the Home Screen).
2. Share button → **Add to Home Screen** → **Add**. The app’s first-run screen shows this with pictures.
3. From then on, open it from the **daisy icon**.

> ⚠️ On iOS, the Home Screen app has **its own storage**, separate from Safari tabs. Anything she
> logs in a Safari tab won’t appear in the installed app. Install first, then use the icon.
> If you set things up for her in Safari first, use **Save a backup** → **Restore** inside the installed app.

## Data safety
- Every tap writes straight to IndexedDB. There’s no Save button and nothing to lose mid-workout. An
  unfinished workout resumes on reopen.
- `navigator.storage.persist()` is requested at first run and at the end of onboarding.
- iOS may still clear data for apps that go **unused for weeks**, so the home screen gently suggests a
  backup every 30 days (`backupNudgeDays` in `theme/config.ts`). Backups go through the iPhone Share
  sheet → *Save to Files* / iCloud Drive / AirDrop / Mail.
- Restoring a backup first saves a copy of the current data.
- Deletions show an **Undo** toast instead of scary confirmation dialogs.

## Reminders
Web apps can’t schedule notifications by themselves, so there are three layers:
1. **In-app**: on planned days the home screen says so (always works).
2. **📅 Add reminders to my Calendar**: creates a weekly repeating iPhone Calendar event with an alert
   on her chosen days and time. No server, works offline, and it’s the most reliable option. **Recommended.**
3. **🔔 Web push** (iOS 16.4+, installed to Home Screen only). The service worker already handles
   `push` events. To actually *send* them you need a tiny server:
   - Generate VAPID keys: `npx web-push generate-vapid-keys`
   - Put the public key and your endpoint URL in `push` in `src/theme/config.ts`
   - The app POSTs `{ subscription, days, time, tz }` to that endpoint. A small scheduled function
     (e.g. a Vercel/Netlify cron calling the `web-push` library) can send a message at the right time.
   Without this, “Turn on notifications” still asks permission and shows a test notification, then
   points her to the Calendar option. It fails gracefully everywhere.

## Feedback notes
**Send me a note** (bottom of the home screen, and Settings → Help) lets her type a problem or an idea.
It adds the app version, iOS version and a few settings at the bottom, then hands it to her iPhone:
- `feedback.phone` set in `src/theme/config.ts` → Messages opens addressed to you, note filled in
- `feedback.email` set → Mail opens instead
- neither → the share sheet opens and she picks Messages and you

Her draft is kept if she backs out. To get a note fixed, paste it into a Claude Code session on this repo.

## Progression rules (`src/config/progression.ts`)
- **Library:** set up for an intermediate lifter (`src/data/exercises.ts`): barbell, dumbbell, machine and
  cable lifts grouped by body area, plus intermediate bodyweight moves (knee and full push-ups, chin-ups,
  dips, core). Each lift has a first-time weight guess; once she logs a real weight the app follows her.
- **Weights:** double progression over 3 sets in each exercise’s rep range (6–10 for big barbell lifts,
  8–12 for most accessories, 10–15 for small isolation lifts). Hit the top of the range on every set → add
  the smallest step (5 lb for most lifts, 2.5 lb for raises and flys, 10 lb for leg press and hip thrust)
  and drop to the bottom of the range; otherwise +1 rep.
- **Missed target:** first miss → repeat the same target; second miss in a row → ease off ~10%. At light
  weights, where one step would be a huge jump, it keeps the weight and drops 2 reps instead.
- **She picks a lighter weight:** the app follows her lead and builds from what she actually did.
- **Bodyweight:** +1 rep up to the top of the range, then suggests a harder variation.
- **Cardio:** +1 min (or +5%, max +5 min) per session; distance +0.1 mi. Planks grow by seconds.
- Suggestions are computed by **replaying her history** through the rules, so editing the rules
  updates every suggestion. No stored state goes stale.
- **Milestones:** each about 15% of the gap from start to goal, rounded to friendly numbers (whole weight
  steps, whole reps, whole minutes, tenths of a mile), at most 8.

## iOS details handled
- `viewport-fit=cover` + `env(safe-area-inset-*)` padding (notch/Dynamic Island, home indicator)
- `apple-mobile-web-app-capable`, status-bar style, title, 180 px opaque `apple-touch-icon`
- Splash screens for every iPhone size from SE to 17 Pro Max (`npm run icons` regenerates)
- The page itself never scrolls (`overflow:hidden` + `overscroll-behavior:none`); only inner areas do,
  so there’s no whole-app rubber-banding
- All inputs ≥16 px (no auto-zoom on focus) while pinch-zoom stays enabled for accessibility
- `touch-action: manipulation` (no double-tap-zoom delay), tap targets ≥ 48 px
- Text size setting includes **Match iPhone** (uses `-apple-system-body` = Dynamic Type)
- Calm mode + `prefers-reduced-motion` turn off bouncing and all easter eggs
- VoiceOver: every control has a spoken label; steppers announce their value; daisy checkboxes are
  real checkboxes

## Future-proofing
- **Cloud sync / accounts:** implement the `Store` interface (`src/data/storage.ts`) against a backend
  and switch it in `src/data/index.ts`. Every screen goes through the interface.
- **Re-skin for someone else:** edit only `src/theme/` (plus the manifest name/colours in
  `vite.config.ts` and `scripts/generate-icons.mjs`, then `npm run icons`).
- **Native App Store app (Capacitor):** no router/URLs, relative asset paths, no server code.
  `npm i @capacitor/core @capacitor/cli @capacitor/ios && npx cap init && npx cap add ios`, set
  `webDir: 'dist'`, then `npm run build && npx cap sync`. For native, swap reminders to
  `@capacitor/local-notifications` (`isNativeApp()` in `src/lib/platform.ts` is ready for that check).
